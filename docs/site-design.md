# Onion 个人网站实现说明

更新：2026-09-21。交互稿已落地为真实 Nuxt 全栈应用，运行方法见项目 README。

## 产品与视觉

这是用于展示自己、博客分享、项目与生活动态的个人站点，以 Innei 为风格参考。沿用中性色、雾紫点缀、柔和光影、舒适留白与轻量交互反馈，保持内容阅读的重心。提供浅色、深色、跟随系统及三种点缀色；支持桌面和移动端。

视觉更新：桌面内容区约 1128px，基础字体 16px、文章正文 18px，手机文章正文 17px。字体改为随项目部署的 Manrope Variable（拉丁字符）与 Noto Sans SC Variable（中文），由 Fontsource 的字体包提供 WOFF2 和 unicode-range 分片，不依赖读者设备预装字体或外部字体 CDN。字体许可证随应用放在 `public/fonts-licenses/`。

采用中性白 / 炭灰底色与少量紫色点缀。顶部导航使用文字及细线选中态；首页标题按首个逗号或英文句号断行，正文、元信息与标题分别设置字重。近期文章采用左侧栏目 / 右侧列表布局，项目使用作品封面展示，生活使用日期轴与手记，让三个栏目各有节奏。立绘保留，背景改为有细网格和低对比站名的展示区，移除漂浮标签与环形光晕。手机采用单栏布局。

Onion 标识采用洋葱切面的层次、字母 O 的轮廓和一枚嫩芽，应用于导航、页脚、登录页、错误页及 favicon。品牌 SVG 与立绘作为项目静态设计资源存放在 `public/brand/` 和 `public/images/`，和应用一起部署。立绘生成说明见 `docs/brand-assets.md`。

首页包含个人介绍、近期文章、项目、生活片段与随想。导航、个人信息、关于、页脚等由 MySQL 提供。Onion 名称与内容可在站点设置及内容后台维护。没有真实已发布内容的栏目显示空状态。生活记录有照片时使用相册式呈现，无照片时使用纸张手记，不生成虚构生活图片。

### 三种内容的展示方式

- 博客：标签筛选、首篇大标题、按年份排列的文章列表与阅读侧栏；详情强调正文、作者和阅读时长。
- 项目：交错排列的大封面、技术栈、开发状态、独立的访问与源码入口；详情采用作品介绍布局。未上传封面时使用由真实项目名生成的几何封面，未填写外链时不显示访问按钮。
- 生活：日期轴、地点与作者信息；有封面时展示照片，无封面时展示便签手记。详情保持日记阅读样式。
- 首页及搜索复用各类型自己的展示组件。三类详情都保留评论、深浅主题及移动端适配。

### 博客标签

文章支持多个标签，保存到版本快照的 metadata.tags；前台仅查询已发布版本。标签导航显示全部文章数及各标签文章数，服务端筛选后分页，顶部标签、文章列表标签、详情页标签均进入独立的 `/zh/tags/Python`（英文 `/en/tags/Python`）一类的标签博客页；页面显示标签名、文章数量、列表和分页，可收藏与分享。标签名称进行 URL 编码，支持中文和特殊字符；切换语言保留标签及页码。旧的 writing?tag 链接继续支持。中英文统计和筛选遵循博客的语言回退规则；没有对应英文发布版本时查询中文。

标签名称不使用固定枚举，可按内容自由扩展。Android、iOS、Java、AI、Python、SpringBoot 仅为初始常用标签，保存在 site_settings.config.writingTags。作者可在站点设置调整，也可以写文章时输入新的标签；已发布文章中的新标签自动出现在导航。常用标签尚无文章时显示 0 和空状态。界面文案仍在 ui_messages；db:init 幂等补齐缺少的配置和文案，不覆盖已有配置，无需新增表结构。

## 权限和评论

- 只有网站作者可登录后台，创建、编辑、发布文章、生活动态和项目，以及上传图片和修改站点设置。
- 没有开放注册或访客写作权限。所有管理 API 都在服务端鉴权。
- 访客可以阅读，并为博客、项目、生活动态填写昵称评论，无需账号。
- 评论默认待审核，作者在后台审核、隐藏和回复。作者回复带有服务端确认的作者标记。评论显示为纯文本，支持回复和分页，并限制提交频率。

## 语言规则

网站文案和博客文章支持中英文。博客没有已发布英文版本时，英文列表、搜索和详情直接展示中文原文。项目与生活使用原文，不要求双语维护。

博客的中文、英文版本分别保存与发布。修改草稿不会改变正在展示的公开文章；界面语言与正文编辑语言分开。语言切换仍保留当前文章，缺少英文时回退中文，而不是跳回列表。

## 写作和图片

已集成 md-editor-v3，支持 Markdown 编辑、预览、工具栏格式、代码块、表格、标题、引用、链接与图片。允许适当安全 HTML 排版，如 u、mark、sup、sub；服务端通过 markdown-it 与 sanitize-html 渲染并过滤可执行内容，浏览器预览使用 DOMPurify。

图片文件存入 `data/uploads/YYYY-MM/随机ID.ext`，MySQL 保存元数据及版本引用。Markdown 通过 `/api/media/ID` 引用图片，限制 8 MB 与 PNG/JPEG/WebP/GIF 格式。未被公开内容引用的图片仅作者可读，关于页与头像引用可公开读。备份需同时备份数据库和上传目录。

## 实际数据模型

| 表                               | 职责                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ |
| site_settings                    | 默认语言、主题、点缀色、头像、导航及博客常用标签 JSON                    |
| site_profiles                    | 中英文站点名称、个人介绍、关于、随想与页脚                               |
| ui_messages                      | 中英文界面文案                                                           |
| users / sessions / auth_attempts | 作者账号、会话摘要与登录限流                                             |
| preferences                      | 访客语言和主题，Cookie 仅缓存渲染偏好与随机标识                          |
| content_items                    | 博客、项目、生活的稳定 ID、作者与归档状态                                |
| content_translations             | 各语言草稿/公开版本指针、公开路径、乐观锁版本号                          |
| content_revisions                | 不可变的标题、路径、摘要、Markdown、封面及分类/标签/项目/生活元数据 JSON |
| media_assets / revision_media    | 图片文件元信息与版本引用                                                 |
| comments / comment_attempts      | 评论、回复、审核状态和评论限流                                           |
| schema_migrations                | SQL 迁移版本和校验摘要                                                   |

每次保存创建新版本，发布事务更新公开指针；公开查询不读草稿。项目字段、分类标签和封面也在版本快照中，避免未发布修改影响前台。发布时检查路径冲突；旧窗口保存会返回版本冲突。

## 一体部署与验证边界

Nuxt 4 + Vue 3 + Nitro API + mysql2。前台、后台与 API 构建成一个 Node 服务、共用端口。MySQL 是独立数据库服务；Docker Compose 管理数据库、初始化任务及应用，图片使用持久卷。SQL 按顺序执行并校验历史文件，重复初始化保留已有账号与内容。

本地使用独立 MySQL 实例存储实际内容，开发实例不连接其他项目数据库。正常初始化关闭示例数据，仅独立测试数据库显式启用测试内容。构建、类型检查、基础测试、独立测试数据库中的 HTTP 集成流程和浏览器检查用于验证当前实现。Docker 配置已提供，是否实际运行容器/部署到服务器应以最终交付记录为准，不能把本地构建当作线上部署。
